# Go Live With Vercel

The canonical production stack is documented in `docs/STACK.md`.

## Deployment

1. Connect this GitHub repository to the Garcia Builder project in Vercel.
2. Set the production branch to `main`.
3. Set the Vercel output directory to `public`, generated by `npm run build:public`.
4. Add the production domains in Vercel and follow the DNS records shown there.
5. Confirm that a push to `main` creates a Vercel production deployment.

GitHub Actions validates the repository. It does not deploy the website.

## Required Integrations

Configure these values in the Vercel project. Never commit secret values.

### Supabase

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` or `SUPABASE_SECRET_KEY`

Use Supabase for authentication, lead storage, result persistence and delivery
status. Configure the production site URL and allowed authentication redirects
with the Garcia Builder production domains.

### Brevo

- `BREVO_API_KEY`
- `BREVO_SENDER_EMAIL`
- `BREVO_SENDER_NAME`

Brevo sends transactional messages, including localized starter-assessment
results. The sender address must be verified in Brevo.

### Zapier

- `ZAPIER_LEAD_WEBHOOK_URL`
- `ZAPIER_MAIN_COACHING_WEBHOOK_URL`
- `ZAPIER_HOT_LEAD_WEBHOOK_URL`
- `ZAPIER_EBOOK_WEBHOOK_URL`

Only configure the hooks used by the active workflow. The API must continue to
store the lead in Supabase even when an optional Zapier notification fails.

## Release Check

Run:

```powershell
npm test
npm run lint
npm run build:public
```

Then verify:

- `/health` reports the expected integration readiness.
- `/go/card` redirects to the canonical `/start` assessment while preserving `utm_source=business_card`, `utm_medium=qr` and `utm_campaign=starter_assessment`.
- A test assessment stores one Supabase lead.
- Brevo sends the result in the selected language.
- Zapier receives one canonical lead event.
- Vercel shows the commit as the active production deployment.
